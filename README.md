# Pomodoro

A simple Pomodoro timer for Android, built as a hands-on exercise for **Kotlin** and **Jetpack Compose**.
The goal is not a feature-rich product but a clean base source that demonstrates modern Android practices:
state-driven UI, unidirectional data flow, coroutines/Flow, and testable timer logic.

## Status

Scaffold only. The Android Studio template (`MainActivity`, theme) is in place and the package folders
are created, but the timer, settings and navigation are not implemented yet.

## Architecture

MVVM with unidirectional data flow (UDF):

```
UI (Composable)  --events-->  ViewModel  --->  Engine / Repository
      ^                           |
      +---- StateFlow<UiState> ---+
```

- **State flows down, events flow up.** Composables are stateless where possible and receive `state` plus an `onEvent` callback.
- **Business logic lives outside the UI.** The countdown logic is a pure Kotlin class so it can be unit-tested on the JVM.
- **Single module, package-by-feature.** Each feature owns its screen, ViewModel and UI state.
- **Manual dependency injection** first (created in an `Application` class); Hilt may be introduced later as a refactoring exercise.

## Getting started

1. Clone the repository and open the root folder in a recent Android Studio.
2. Let Gradle sync. `local.properties` (SDK path) is generated by Android Studio and must not be committed.
3. Run the `app` configuration on a device or emulator that satisfies `minSdk 36`.
4. Run unit tests: `./gradlew test`. Run instrumented tests: `./gradlew connectedAndroidTest`.

## Conventions

- Commit messages use a prefix: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`.
- One logical step per commit (for example: static UI, then ViewModel, then animation, then settings).
- Composables are `PascalCase`; every screen-level composable has a `@Preview`.
- UI state classes are immutable (`data class` with `val` properties only).
